Starting this site from a blank page

18 September 2026 · 3 min read · meta, web

This site is a folder of HTML files. There is no generator, no package manager and no workflow file — just markup, one stylesheet and one small script. That was a deliberate choice, and it is worth writing down before nostalgia rewrites the reasoning.

What “no build step” actually buys

The obvious win is that nothing stands between editing a file and seeing the result. There is no dependency tree to update, so there is no dependency tree to break. A file pushed to the repository is the file served to a browser, byte for byte.

The less obvious win is that the site keeps working. A static page written today will still render in ten years, which is not something that can be said for every tool that generates static pages.

If the output of a build is a website, keeping the website and deleting the build is a legitimate design decision.

What gets harder

Shared markup is the real cost. There is no layout system to inherit, so the header and footer are copied into every page. That is fine at this size and painful at a hundred pages.

  • Adding a post means editing two files: the post and the index.
  • Renaming a section means a search and replace across pages.
  • Nothing validates the markup except careful reading.

The rules that keep it manageable

  1. Use relative paths for every internal link and asset.
  2. Keep the stylesheet token-driven, so re-theming is one block.
  3. Treat JavaScript as optional; nothing important may depend on it.
  4. Duplicate the navigation rather than rendering it from a script.

A link that works everywhere

The fourth rule matters more than it sounds. A navigation bar injected by a script looks tidy in the repository and then disappears when a page is opened from disk, because fetching a partial from file:// is blocked. Writing the links out avoids the problem entirely. 

<nav class="site-nav" aria-label="Main">
  <ul>
    <li><a href="../index.html">Home</a></li>
    <li><a href="index.html" aria-current="page">Blog</a></li>
  </ul>
</nav>

The aria-current attribute does double duty: it tells a screen reader which page is open, and it is a reliable CSS hook for styling the active link.

The trade-offs, side by side

Concern Hand-written Generated
Time to first page Minutes An afternoon of setup
Adding a post Copy a file, edit two places Drop a file in a folder
Breaks over time Rarely Whenever dependencies move
Comfortable ceiling Tens of pages Thousands

Where this leaves the site

A site this size does not need machinery. When it grows past the comfortable ceiling, the markup is plain enough to move into any generator without a rewrite — which is exactly the escape hatch worth keeping open.
