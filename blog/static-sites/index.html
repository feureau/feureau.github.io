Static sites that are not boring

5 August 2026 · 4 min read · web, tools

A plain page with a browser-default look reads as unfinished, which makes the content look unfinished too. None of the fixes below require a framework; they are a handful of CSS rules that a reader will never consciously notice.

Set the type first

Almost every improvement in how a page feels comes from three decisions: a line length between sixty and seventy-five characters, a line height near 1.6, and a heading scale that does not jump around. 

:root {
  --prose: 46rem;      /* the reading column */
  --gap: clamp(1rem, 2vw, 1.5rem);
}

.prose {
  max-width: var(--prose);
  line-height: 1.65;
}

Using clamp() for spacing means one rule covers phone, laptop and wide monitor without a single breakpoint.

Pick a theme from tokens, not from literals

A dark palette is no longer a feature to advertise; it is what people expect. This site ships a single dark theme, and every colour in it comes from a custom property at the top of the stylesheet, which is what makes the choice reversible: to follow the operating system instead, the same tokens move under a prefers-color-scheme block and a light set is added beside them.

  • Keep every colour in one place so the palettes cannot drift apart.
  • Check text contrast against the real background, not in theory.
  • Paint backgrounds with tokens, never with literal colour values.
  • Set color-scheme so scrollbars and form controls match.

Print is a theme too

Anyone printing a page for paper wants the navigation gone, the colours flattened and the links visible as text. A print block is a dozen lines and turns a web page into a document. 

@media print {
  .site-header, .site-footer, .skip-link { display: none; }

  a[href^="http"]::after {
    content: " (" attr(href) ")";
  }
}

Make the nice things optional

The mobile menu here is a hidden checkbox with a styled label. That sounds like a trick, and it is, but it means the menu opens even when a script fails to load. JavaScript is left to handle only the parts that are genuinely additive.

Feature Depends on JavaScript?
Navigation and content No
Dark mode No
Tag filtering on the blog Yes, but the full list still renders
Footer year Yes, with a static fallback

Build the page so it works with nothing switched on, then switch things on.

Respect the reader’s settings

Two lines of CSS handle visitors who ask for less motion, and a visible focus outline handles everyone who navigates by keyboard. Neither is decoration; both are the difference between a page that works and a page that merely loads.
